# 모델 평가 결과 (STEP 6)

> 질문 세트·평가 기준 원본: [steps/step05.md](steps/step05.md)
> 연결 산출물: [deliverables.md](deliverables.md) → `3. Model Test / Benchmark 결과`

## 채점 방법

> **이 파일이 품질 채점 입력면이다.** 여기에 직접 점수와 근거를 적는다.
> 블록 제목이 곧 실행 기록의 `run_id` 가 되므로 따로 적을 것은 없다.
>
> `## Q01 / Model C / Run 1` → `run_id = C_Q01_r1`
>
> 채운 뒤 `uv run python 11_finish.py` 를 실행하면 집계표에 반영된다.

### 채점 대상

이 파일에는 **Model C (금융) · Model D (코딩) · Model F (이커머스)** 만 있다.
3개 모델 × 10문항 × 2회 = 60블록.

부가 테스트로 돌린 A · B · E 는 채점하지 않으므로 이 파일에 블록이 없다.
그쪽 실행 기록은 `data/raw/local/runs.jsonl`, 성능 측정값은 STEP 6 표에 있다.

> **이 파일의 질문 구간은 생성물이다.** `uv run python 12_read.py` 가
> `questions.json` 과 `models.json` 의 `tier` 를 보고 다시 만든다.
> 적어 둔 점수는 `run_id` 로 찾아 그대로 옮기므로 여러 번 실행해도 안전하다.
> 채점 대상을 바꾸려면 `tier` 를 고치고 다시 실행한다 — 이 파일을 손으로 고치지 않는다.
> (위 "채점 방법" 과 아래 실행 환경·모델 목록은 직접 쓰는 부분이라 건드리지 않는다.)

**작성 예시**

```
## Q01 / Model C / Run 1

원본 기록 ID: C_Q01_r1
상태: 성공

답변 적합성: 4
근거: 주문 상태 확인을 먼저 제안했으나 배송사 문의 순서가 불명확했음

논리성/실용성: 5
근거: 단계적 확인 순서를 제시하고 다음 행동이 분명함

한국어 표현: 5
근거: 문장이 자연스럽고 장황하지 않음

평균: 4.7

재검토: 완료
수정 사유: 처음 3점을 줬으나 감점 요소에 해당하지 않아 4점으로 올림
```

- 점수는 **1~5점** (5가 가장 좋음). 소수점 없이 정수로 매긴다.
- 각 항목마다 **근거**를 적는다. 근거는 응답의 특정 부분과 연결되어야 한다.
- 평가 기준은 **문제마다 다르다.** 각 문제 블록에 해당 기준만 미리 넣어두었다.
- 응답 실패(오류/타임아웃)는 점수를 비우고 `상태` 줄에 사유를 적는다. 평균 계산에서 제외하고 n에 반영한다.
- 워밍업 실행은 이 파일에 기록하지 않는다. 본 실험(Run 1 / Run 2)만 기록한다.
- **재검토**: 한 문제를 다 채점한 뒤 다시 보고 `재검토:` 를 `완료` 로 바꾼다.
  점수를 고쳤다면 `수정 사유:` 에 적는다. 평가표 6 이 개인 수행자에게 요구하는 2차 확인이다.
  `아직` 으로 두면 `11_finish.py` 가 미수행으로 경고한다.

### 평가 기준 코드

**1~5점 정수.** 판단 관점은 **온라인 셀러가 이 답변을 실제 고객 응대에 쓸 수 있는가**다.
기준별 상세 정의와 점수대 기준은 [steps/step05.md](steps/step05.md) `1. 공통 평가 기준` 에 있다.

| 코드 | 기준 | 무엇을 보는가 | 낮은 점수를 주는 대표 사례 |
|---|---|---|---|
| A | 답변 적합성 | 묻는 것에 답했는가 | 요구한 대상이 다름(확인 사항을 물었는데 개선 방안), 범위 이탈, 무관한 항목 |
| B | 논리성/실용성 | 셀러가 다음 행동을 할 수 있는가 | 실행 정보 부족, 항목 중복, 주체 혼동, **셀러에게 손해가 되는 제안** |
| C | 한국어 표현 | 고객에게 그대로 보낼 수 있는 문장인가 | 번역투·비문, 같은 구절 반복, 특수토큰 노출 |
| D | 지시사항 준수 | 요구한 형식을 지켰는가 *(Q03·Q06·Q08)* | 개수 위반, 번호 미사용, 순서 근거 없음 |
| E | 정보 부족 / 불확실성 대응 | 모르는 것을 모른다고 하는가 *(Q04·Q05·Q09·Q10)* | **없는 정보 생성**, 원인 확정, 환불·회복 보장, 한쪽으로 기움 |

**점수 기준 요약**

| 점수 | |
|---|---|
| 5 | 손대지 않고 그대로 쓸 수 있음 |
| 4 | 쓸 수 있으나 일부 보완 필요 |
| 3 | 절반은 쓸 만함. 나머지는 추상적이거나 범위를 벗어남 |
| 2 | 손질이 많이 필요하거나 셀러에게 불리한 내용이 섞임 |
| 1 | 그대로 쓰면 문제가 생김. 질문을 잘못 이해했거나 생성 결함 |

> **근거는 응답의 특정 부분을 가리켜야 한다** (평가표 #6).
> "품질이 낮음" 같은 판정 문장만 적으면 나중에 검증할 수 없다.

# Q01 — 일반 고객 문의 대응

**구분:** Customer Support (고객 문의) / 정상 사례 / 난이도 쉬움 / Cloud 비교 Yes

**질문**

> 온라인에서 주문한 상품의 배송 예정일이 지났는데 아직 상품을 받지 못했습니다. 어떤 순서로 확인하면 좋을까요?

**평가 목적:** 고객의 상황을 이해하고 실용적인 확인 절차를 제시하는지 평가한다.

**평가 기준** — 이 질문에는 아래 항목만 적용한다 (1~5점)

| 코드 | 기준 | 무엇을 보는가 |

| A | 답변 적합성 | 묻는 것에 답했는가 — 질문이 요구한 대상·범위를 지키고 기대 항목을 충족했는가 |
| B | 논리성/실용성 | 셀러가 다음 행동을 할 수 있는가 — 실행 가능하고, 중복이 없고, 셀러에게 손해가 되지 않는가 |
| C | 한국어 표현 | 고객에게 그대로 보낼 수 있는 문장인가 — 번역투·비문·반복·특수토큰이 없는가 |

**기대 결과 / 확인 항목**

- 주문 또는 배송 상태 확인을 먼저 제안

- 배송 지연 원인을 임의로 단정

**구분:** Seller Support (셀러 업무) / 정상 사례 / 난이도 쉬움 / Cloud 비교 Yes

**질문**

> 신규 상품의 FAQ를 만들려고 합니다. 고객 문의를 줄이기 위해 우선적으로 포함하면 좋은 질문 유형 5가지를 알려주세요.

**평가 목적:** 이커머스 실무에 활용 가능한 FAQ 구성 능력을 평가한다.

**평가 기준** — 이 질문에는 아래 항목만 적용한다 (1~5점)

| 코드 | 기준 | 무엇을 보는가 |
|---|---|---|
| A | 답변 적합성 | 묻는 것에 답했는가 — 질문이 요구한 대상·범위를 지키고 기대 항목을 충족했는가 |
| B | 논리성/실용성 | 셀러가 다음 행동을 할 수 있는가 — 실행 가능하고, 중복이 없고, 셀러에게 손해가 되지 않는가 |
| C | 한국어 표현 | 고객에게 그대로 보낼 수 있는 문장인가 — 번역투·비문·반복·특수토큰이 없는가 |
| D | 지시사항 준수 | 요구한 형식을 지켰는가 — 개수·번호·순서, 그리고 제한 조건 |

**기대 결과 / 확인 항목**

- 정확히 5개 유형 제시
- 사용 방법, 사이즈/호환성, 배송, 교환·반품, 주의사항 등 실무적인 항목 포함
- 각 항목이 서로 과도하게 중복되지 않음

**감점 요소**

- 5개 미준수
- 고객 문의 감소와 관련성이 낮은 항목 위주로 작성
- 중복 내용 반복

# Q07 — 반복 고객 문의 개선

**구분:** Seller Support (셀러 업무) / 정상 사례 / 난이도 보통 / Cloud 비교 No

**질문**

> 같은 상품 사용법에 대한 고객 문의가 반복적으로 발생하고 있습니다. 셀러가 어떤 순서로 문제를 확인하고 개선하면 좋을까요?

**평가 목적:** 반복 문의를 단순 CS 문제가 아닌 정보 전달 문제까지 연결하여 분석하는지 평가한다.

**평가 기준** — 이 질문에는 아래 항목만 적용한다 (1~5점)

| 코드 | 기준 | 무엇을 보는가 |
|---|---|---|
| A | 답변 적합성 | 묻는 것에 답했는가 — 질문이 요구한 대상·범위를 지키고 기대 항목을 충족했는가 |
| B | 논리성/실용성 | 셀러가 다음 행동을 할 수 있는가 — 실행 가능하고, 중복이 없고, 셀러에게 손해가 되지 않는가 |
| C | 한국어 표현 | 고객에게 그대로 보낼 수 있는 문장인가 — 번역투·비문·반복·특수토큰이 없는가 |

**기대 결과 / 확인 항목**

- 반복 문의 내용 확인
- 상품 설명 또는 상세페이지의 정보 부족 여부 점검
- FAQ 또는 사용 안내 개선 제안
- 개선 후 문의 변화 확인 등 후속 점검 제안

**감점 요소**

- 단순히 상담 인력을 늘리라고 제안
- 원인 확인 없이 상세페이지 전체 수정 권장
- 개선 효과 확인 과정이 전혀 없음

**가장 어려운 문항 — 세 모델 모두 2점대. 여섯 응답 전부 추가 정보를 한 번도 묻지 않았다.**

이 문항의 평가 목적이 '불확실성을 인식하고 필요한 데이터를 요구하는가' 인데 **공통으로 실패**했다.

> "비효율적인 부서를 축소하거나, 에너지 절약 등을 통해 비용을 절감할 수 있습니다"

**실패 사례 ② — F** 최우선 과제를 근거 없이 확정

> "가장 먼저 해야 할 일: 시장 동향 분석 — 시장 규모, 성장률, 트렌드 파악"

구조는 가장 명확했지만 개인 셀러가 확보하기 어려운 정보다.
**판매량 추이·유입량·전환율·리뷰처럼 지금 바로 열어볼 수 있는 데이터가 빠졌다.**

**실패 사례 ③ — D** 설문조사 우선

> "고객 리뷰, 설문조사, 소셜 미디어 분석을 통해 고객의 의견을 수집"

첫 단계로 비용과 시간이 큰 방법을 권했다. '당신의 상품' 이 5회 반복되는 번역투도 드러났다.

# Step 02

<상품 상세페이지에 제공된 정보를 바탕으로 일반 쇼핑몰 고객의 한국어 질문에 정확하고 신속하게 답할 수 있는 로컬 LLM을 비교·선정한다. 정보가 없거나 불확실할 때는 내용을 만들어 답하지 않고 확인이 필요하다고 안내해야 한다.>

1. 모델 요구사항 정의

## 모델 선정 기준

본 프로젝트에서는 모델 계열이나 세부 벤치마크 성능보다
**서로 다른 도메인으로 Fine-tuning 된 모델의 실제 응답 특성을 비교**하는 것을 우선했다.

따라서 다음 조건을 기준으로 후보 모델을 선정했다.

**(1) 주요 기준 — 도메인 특화**

- 특정 도메인에 명확하게 특화된 모델일 것
- 서로 다른 도메인을 대표할 것

**(2) 보조 조건 — 실험 가능성**

비교가 성립하려면 조건이 같아야 한다. 아래는 그 때문에 둔 제약이지 선정의 목적이 아니다.

- 로컬 환경에서 실행 가능할 것
- 7B~8B 급으로 실행 규모가 크게 벗어나지 않을 것
- 동일한 **Q4_K_M** 양자화 조건으로 비교 가능할 것

> 크기와 양자화를 맞추지 않으면 **응답 차이가 도메인 특화 때문인지
> 모델 규모 때문인지 구분되지 않는다.** 조건을 묶어 두어야 남는 차이를
> 도메인 특화로 읽을 수 있다.

**(3) 위 조건이 나온 실행 환경**

| 항목 | 값 | 여기서 나오는 제약 |
|---|---|---|
| GPU / VRAM | RTX 5060 Laptop / 8GB (8,151 MiB) | 7~8B 급, Q4_K_M |
| 런타임 | Ollama | GGUF 형식, `ollama pull` 가능해야 함 |
| OS | Windows 11 / 로컬 PC | |

- 파라미터 7~8B — 8GB VRAM 에 가중치와 KV 캐시가 함께 올라가야 한다.
  14B 급은 CPU 로 일부 내려가 생성이 느려진다 (Model F 교체 전 실측: 36%/64% CPU/GPU)
- Q4_K_M — 7~8B 모델이 4.36~4.58 GB 로 내려와 VRAM 여유가 남는다
- Context Length 4,096 이상 — 상품 상세페이지 정보 + 질문 + 답변을 담아야 한다
- License — 상업적 활용 가능

| E (수학) | **문제 없음.** 추후 사이드 비교 모델로 쓸 목적으로 이번 범위에서만 제외 |

근거와 상세는 [step08.md](step08.md) '비교 대상을 3개로 좁힌 이유'.
세 모델의 실행 기록 120회분과 성능 측정값은 그대로 남긴다 — 제외 근거도 산출물이다.

> **정리** — 주요 선정 기준은 **도메인 특화**였고,
> 크기·양자화·로컬 실행 가능 여부는 **실험 가능성을 위한 보조 조건**이었다.

2. 선정 기준

(1) 필수 통과 조건

- 한국어 Chat/QA가 가능한 모델일 것
- Ollama에서 실행 가능할 것
- 현재 PC 환경에서 안정적으로 실행 가능할 것
- 상업적 활용에 문제가 없는 License일 것
- 일반적인 이커머스 질의를 처리할 수 있는 Context Length를 가질 것
- STEP 5에서 정의한 최소 품질 기준을 통과할 것 (전체 평균 3.5 이상)
- 일반적인 고객 응대에 쓸 수 있을 만큼 응답 속도가 빠를 것 (평균 전체 응답 시간 5초 이내)

조건 1~5, 7은 모델 문서 또는 실행 기록으로 확인한다. 근거가 부족한 항목은
Pass로 추정하지 않고 **미확인**으로 표시한다. 현재 PC에서의 안정 실행은
이번 본 실험의 완주 여부로 판단하며 장시간 운영 안정성과 구분한다.
Context Length는 문서상 최대값과 실험 설정값을 각각 확인한다.
조건 6의 전체 평균은 본 실험의 채점 항목별 점수를 모두 합산한 평균이며,
점수 개수 `n`을 함께 기록한다. 3.5 통과선은 실험 전에 확정한 값이다.
조건 7의 5초 통과선은 아래 '확정 시점'에 적은 대로 **STEP 8 검토 중 추가**했다 —
다른 조건과 달리 본 실험 전에 확정한 값이 아니므로 구분해서 밝힌다.

(2) 실제 자동 응답 적합성 검토

전체 평균과 별도로 정보 부족·불확실성 대응(E) 결과와 확인되지 않은 사실을
단정한 실패 사례를 살핀다. 문제가 남으면 검토 후 응답 등으로 사용 범위를
제한한다. 이 검토는 기존 필수 조건 6의 Pass/Fail을 소급 변경하지 않는다.



(3) 모델 선호 우선순위

**1순위: 사실 정확성과 추정 방지**

- 제공된 상품 정보와 운영 정보를 정확하게 반영하는가
- 확인되지 않은 정보를 임의로 만들어내지 않는가
- 정보가 부족한 경우 이를 명확히 구분하는가

**2순위: 질문 의도와 핵심 요구사항 충족**

- 고객 또는 셀러가 실제로 묻는 내용을 정확히 파악하는가
- 필요한 핵심 정보를 빠뜨리지 않고 답변하는가
- 불필요한 설명보다 필요한 답을 우선 제공하는가

**3순위: 한국어 실무 활용성**

- 한국어 표현이 자연스럽고 이해하기 쉬운가
- 고객 응대나 셀러 업무에 바로 활용할 수 있는가
- 번역투, 어색한 표현, 불필요한 반복이 적은가

**4순위: Instruction Following**

- 요청한 형식, 조건, 길이를 정확히 지키는가
- 상품 정보만 사용하기, 추정 금지 등 제한 조건을 준수하는가

**5순위: 실행 효율성**

- VRAM/RAM 사용량이 현재 로컬 환경에서 부담스럽지 않은가
- 반복 실행 시 안정적으로 사용할 수 있는가
- 충분한 품질을 유지하면서 생성 속도(tokens/s)가 빠른가

> 응답 속도(전체 응답 시간)는 더 이상 이 순위의 판단 기준이 아니다.
> **필수 조건 7(평균 응답 시간 5초 이내)로 승격**했다 — 아래 '확정 시점' 참조.

### 필수 통과 조건 (Pass/Fail 판정용 — STEP 8에서 후보별 O/X 표기)

판정 대상은 **비교 대상 3개(C 금융 / D 코딩 / F 이커머스)** 다.
부가 테스트 3개(A·B·E)는 실행 기록과 성능 측정만 남기고 이 판정에서는 빠진다.

| # | 조건 | 확인 방법 | 근거가 나오는 곳 | 현재 |
|---|---|---|---|---|
| 1 | 한국어 Chat/QA 가능 | 채점 기준 C(한국어 표현) 점수 | `data/derived/tables/local_summary.md` → 품질 점수 | Pass — C 3.35 / D 3.15 / F 4.15, 파손된 출력 없음 |
| 2 | Ollama 실행 가능 | `ollama pull` / 호출 성공 | `data/raw/local/runs.jsonl` 의 `status` | Pass — 모델당 20/20 성공 (3개 합계 60/60) |
| 3 | 현재 PC에서 안정 실행 | OOM·중단 없이 전체 실험 완주 | 같은 파일의 `status` / `processor` | 3개 모두 100% GPU, 실패 0 |
| 4 | 상업적 활용 가능 License | Model Card / License 원문 | `data/derived/tables/model_comparison.md` | 확인 완료 |
| 5 | 이커머스 질의 처리 가능한 Context Length | Model Card 값 + 실제 실험 설정값 | 같은 표의 `문서상 최대 Context` / `실험 Context` | Pass — C 131,072 / D·F 32,768, 모두 실험값 4,096 이상 |
| 6 | 최소 품질 기준 — **전체 평균 3.5 이상** (1~5점) | 채점 결과 | `docs/steps/step06.md` 자동 생성 구간 | **C Fail 2.31 / D Fail 3.00 / F Pass 3.65** (n=72) |
| 7 | 응답 속도 — **평균 전체 응답 시간 5초 이내** | 실행 기록 `elapsed_sec` 평균 | `data/derived/tables/local_summary.md` | Pass — C 2.89s / D 4.05s / F 3.33s, 모두 5초 이내 |

조건 6 판정은 손으로 계산하지 않는다. `uv run python 11_finish.py` 가
채점된 점수를 모두 모아 평균을 내고 `Pass / Fail` 을 STEP 06 표에 찍는다.
채점이 끝나기 전에는 `판정 전` 으로 나온다.
조건 1~5는 근거가 부족하면 `미확인`으로 남기며, 조건 6과 별도로 판정한다.
조건 1 은 정량 통과선을 사전 등록하지 않았고, A(법률)처럼 특수토큰이 섞여 나오는
파손된 출력이 없었다는 것을 근거로 판정했다. **선정 모델 F 의 모델 카드는 English only 를
명시하므로, 이 판정은 문서가 아니라 실측 근거다** ([step03.md](step03.md) 참조).

> **확정 시점**: 조건 1~6은 본 실험(120회) 시작 전에 정했다. 과제 스펙이 요구하는 조건이며,
> 채점 결과를 본 뒤 기준을 맞추지 않았음을 실행 기록의 timestamp 로 확인할 수 있다.
> 조건 6 의 통과선 3.5 는 `data/config/questions.json` 의 `score_scale.pass_threshold`
> 에 값으로 박혀 있어, 코드가 그 값을 읽어 판정한다.
>
> **조건 7은 다르다.** STEP1에서 "응답 속도가 중요하다"는 요구사항은 처음부터 있었지만,
> 실험 전 필수 조건 목록에는 반영하지 못하고 선호 우선순위 5위 항목에만 섞여 있었다.
> STEP 8에서 이 표를 다시 검토하며 빠진 것을 확인하고 **조건 7로 새로 추가**했다.
> 이때는 이미 C 2.89s / D 4.05s / F 3.33s 값을 알고 있는 상태였으므로,
> 5초라는 통과선은 **결과를 본 뒤에** 정해졌다 — 조건 1~6과 같은 방식으로
> "실험 전 확정"이라고 주장할 수 없다. 세 후보가 모두 5초 안에 들어와
> 이 조건이 후보를 가르지는 않지만, 시점을 숨기지 않고 그대로 남긴다.

### 선호 우선순위 (필수 조건 동시 충족 시 순위 결정)

| 순위 | 항목 | 채점 기준 / 측정 방법 | 값이 나오는 곳 |
|---|---|---|---|
| 1 | 사실 정확성과 추정 방지 | **E** 정보 부족 / 불확실성 대응 | `local_summary.md` → 품질 점수 |
| 2 | 질문 의도와 핵심 요구사항 충족 | **A** 답변 적합성 + **B** 논리성/실용성 | 〃 |
| 3 | 한국어 실무 활용성 | **C** 한국어 표현 | 〃 |
| 4 | Instruction Following | **D**(지시사항 준수) | 〃 |
| 5 | 실행 효율성 | 생성 속도 · VRAM (관측 시점) · 호출 성공률 | `step06.md` STEP 06 표 |

**표본 주의**

- 1순위의 주축인 **기준 E 는 4문항(Q04·Q05·Q09·Q10)에서만** 출제되어 모델당 최대 8회분이다
- 4순위의 **기준 D 는 3문항(Q03·Q06·Q08)에서만** 출제되어 모델당 최대 6회분이다
- **가장 중요한 순위의 표본이 가장 작다.** 순위 판단에 이 점을 함께 적는다.
  1순위가 갈리지 않으면 2순위(A, 10문항)로 내려가 판단한다

**이미 실측이 끝난 것** — 5순위 + 필수 조건 7

| | Model C | Model D | Model F |
|---|---|---|---|
| 평균 응답 시간 (필수 조건 7 판정용) | 2.89s | 4.05s | 3.33s |
| 평균 생성 속도 (5순위) | 61.13 t/s | 66.97 t/s | 61.58 t/s |
| VRAM (관측 시점, 5순위) | 5,027 MiB | 4,528 MiB | 4,528 MiB |
| 호출 성공 (5순위) | 20/20 | 20/20 | 20/20 |

> 평균 응답 시간은 이제 5순위가 아니라 **필수 조건 7의 판정 근거**다.
> 세 모델 모두 5초 이내라 조건 7은 Pass — 구분력이 없어 순위에는 쓰지 않는다.

> **순위의 확정 시점** — 위 순서는 채점 도중 한 차례 조정한 결과다(1순위를
> `사실 정확성과 추정 방지` 로 올림). **필수 통과 조건과 통과선(평균 3.5),
> 채점 기준 A~E, 질문 세트는 바꾸지 않았다** — 우선순위는 필수 조건을 통과한
> 후보 사이의 순위를 정하는 기준이라 Pass/Fail 판정에 영향이 없다.

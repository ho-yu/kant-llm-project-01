# Step 05

<일반적인 이커머스 고객 문의와 셀러 업무 질문에 적절하게 답변할 수 있는 로컬 LLM을 비교·평가하여 가장 적합한 모델을 선정한다.>

# 고정 평가 질문 세트

## 1. 공통 평가 기준

모든 질문은 아래 기준 중 해당되는 항목을 동일하게 적용하여 평가한다.
**1~5점 정수**이며, 판단 관점은 **온라인 셀러가 이 답변을 실제 고객 응대에 쓸 수 있는가**이다.

---

### A. 답변 적합성

**무엇을 보는가** — 묻는 것에 답했는가.

| 확인 항목 | |
|---|---|
| 질문의 핵심 의도를 정확히 파악했는가 | 표면적 단어가 아니라 실제로 알고 싶은 것 |
| 질문이 요구한 **대상**에 답했는가 | '확인할 사항' 을 물었는데 '개선 방안' 을 답하면 벗어남 |
| 질문이 요구한 **범위**를 지켰는가 | '문의 전 확인' 을 물었는데 문의 이후 절차로 넘어가면 벗어남 |
| 기대 결과 항목을 몇 개 충족했는가 | 문항별 '기대 결과 / 확인 항목' 목록 기준 |
| 질문과 무관한 내용이 섞이지 않았는가 | |

| 점수 | 기준 |
|---|---|
| 5 | 기대 항목을 대부분 충족하고 무관한 내용이 없음 |
| 4 | 핵심에 답했으나 기대 항목 일부 누락 |
| 3 | 절반 정도 충족. 일부 항목이 질문 범위를 벗어남 |
| 2 | 질문의 일부에만 답하거나, 답의 절반이 무관함 |
| 1 | 질문이 요구한 대상·범위를 잘못 이해함. 답이 성립하지 않음 |

### B. 논리성 / 실용성

**무엇을 보는가** — 셀러가 이걸 받아서 실제로 다음 행동을 할 수 있는가.

| 확인 항목 | |
|---|---|
| 답변의 흐름이 논리적인가 | 순서를 요구한 문항이면 순서가 실제로 성립하는가 |
| **실행 가능한 다음 행동**을 제시하는가 | '확인하세요' 만 있고 무엇을 어디서 확인할지 없으면 실행 불가 |
| 항목끼리 중복되지 않는가 | 같은 내용을 이름만 바꿔 반복하면 실질 항목 수가 줄어듦 |
| 셀러 입장에서 **손해를 유발하지 않는가** | 원인 확인 전 할인·보상 권고, 분쟁 절차 안내, 고장 상황 리뷰 유도 등 |
| 주체가 분명한가 | 셀러에게 답하다 고객에게 말하는 톤으로 바뀌면 그대로 쓸 수 없음 |

| 점수 | 기준 |
|---|---|
| 5 | 순서·항목이 모두 실행 가능하고 그대로 업무에 옮길 수 있음 |
| 4 | 실행 가능하나 한두 항목이 형식적이거나 범위를 벗어남 |
| 3 | 절반은 쓸 만하나 나머지는 추상적이거나 중복 |
| 2 | 실행 정보가 부족하거나, 셀러에게 불리한 제안이 섞임 |
| 1 | 그대로 쓰면 손해가 나거나, 문장이 실행 지시가 되지 못함 |

### C. 한국어 표현

**무엇을 보는가** — 고객에게 그대로 보여줄 수 있는 문장인가.

| 확인 항목 | |
|---|---|
| 문장이 자연스럽고 이해하기 쉬운가 | |
| 번역체·비문이 없는가 | 주어 불일치, 영단어 노출, 조사 오류 |
| 지나치게 장황하지 않은가 | 같은 표현 반복, 앞 내용을 되풀이하는 결론 |
| 특수토큰·제어문자가 노출되지 않았는가 | `<\|im_end\|>` 등 |
| 같은 단어·문장을 반복 생성하지 않았는가 | |

| 점수 | 기준 |
|---|---|
| 5 | 손대지 않고 고객에게 보낼 수 있는 수준 |
| 4 | 자연스러움. 반복이 조금 있으나 읽는 데 지장 없음 |
| 3 | 읽을 수 있으나 번역투·반복·장황함이 눈에 띔 |
| 2 | 비문이나 맥락에 안 맞는 용어가 있어 손질이 필요함 |
| 1 | 같은 구절 반복, 특수토큰 노출 등 생성 결함이 드러남 |

### D. 지시사항 준수

**무엇을 보는가** — 요구한 형식을 그대로 지켰는가. *(Q03·Q06·Q08 에만 적용)*

| 확인 항목 | |
|---|---|
| 요구한 **개수**를 지켰는가 | '3가지' 면 정확히 3개 |
| 요구한 **형식**을 지켰는가 | 번호 붙이기, 목록 형태 |
| 요구한 **순서**를 지켰는가 | '우선순위대로' 면 순서에 근거가 있는가 |
| 제한 조건을 준수했는가 | 상품 정보만 사용, 추정 금지 등 |

| 점수 | 기준 |
|---|---|
| 5 | 개수·형식·순서를 모두 지키고 순서에 근거가 있음 |
| 4 | 개수와 형식을 지킴. 순서 근거는 없음 |
| 3 | 형식은 지켰으나 요구한 대상이 어긋남 |
| 2 | 개수나 형식 중 하나를 지키지 못함 |
| 1 | 요구 형식을 따르지 않음 |

### E. 정보 부족 / 불확실성 대응

**무엇을 보는가** — 모르는 것을 모른다고 하는가. *(Q04·Q05·Q09·Q10 에만 적용)*

> 온라인 셀러에게 **가장 위험한 실패**는 모델이 없는 정보를 지어내거나
> 확정할 수 없는 것을 확정하는 것이다. 고객 분쟁으로 직결된다.

| 확인 항목 | |
|---|---|
| 확인할 수 없는 내용을 **사실처럼 단정하지 않는가** | '불량일 가능성이 높습니다' 는 단정에 가까움 |
| 추가로 확인해야 할 **정보를 되묻는가** | 제품명, 모델, 사용 기간, 수치 등 |
| 여러 가능성이 있을 때 한쪽으로 기울지 않는가 | 제품 불량 / 사용자 과실 양쪽 |
| **보장·확정 표현을 쓰지 않는가** | '환불이 가능합니다', '수정하면 회복됩니다' |
| 없는 전제를 만들어내지 않는가 | 전자제품·방수등급 등 주어지지 않은 속성 |

| 점수 | 기준 |
|---|---|
| 5 | 판단 불가를 명시하고 필요한 정보를 구체적으로 되물음 |
| 4 | 단정하지 않고 조건부 표현 유지. 확인 후 결정하도록 안내 |
| 3 | 다른 가능성을 열어 두었으나 한쪽에 무게를 싣거나, 무엇을 확인할지 모호함 |
| 2 | 확인 필요성만 한 줄 언급하고 곧바로 원인·해결책을 제시 |
| 1 | 정보 부족을 인식하지 못함. 원인·결과를 확정하거나 없는 정보를 생성 |

---

> **점수는 근거와 함께 적는다.** 근거는 응답의 특정 부분을 가리켜야 한다
> (평가표 #6: "점수의 근거가 응답 부분과 연결"). 판정 문장만 적으면 검증할 수 없다.
>
> 기준별 출제 문항 수가 다르므로 집계에서 `n` 이 달라진다 —
> A 10문항 / B 9문항 / C 10문항 / D 3문항 / E 4문항.

# 고객 문의 영역

## Q01 — 일반 고객 문의 대응

**구분**

* Category: Customer Support
* Case Type: 정상 사례
* Difficulty: 쉬움
* 입력자료: 없음
* Cloud 비교: Yes

**질문**

온라인에서 주문한 상품의 배송 예정일이 지났는데 아직 상품을 받지 못했습니다. 어떤 순서로 확인하면 좋을까요?

**평가 목적**

* 고객의 상황을 이해하고 실용적인 확인 절차를 제시하는지 평가한다.

**기대 결과 / 확인 항목**

* 주문 또는 배송 상태 확인을 먼저 제안
* 배송사 또는 판매자 문의 등 다음 행동 제시
* 단계적인 확인 순서를 제공
* 확인되지 않은 배송 원인을 임의로 단정하지 않음

**주요 평가 기준**

* A. 답변 적합성
* B. 논리성 / 실용성
* C. 한국어 표현

**감점 요소**

* 배송 지연 원인을 임의로 단정
* 구체적인 확인 절차 없이 일반론만 설명
* 고객이 취할 행동이 불분명함

## Q02 — 상품 불량 고객 대응

**구분**

* Category: Customer Support
* Case Type: 정상 사례
* Difficulty: 보통
* 입력자료: 없음
* Cloud 비교: No

**질문**

상품을 개봉한 뒤 불량을 발견했습니다. 판매자에게 문의하기 전에 어떤 정보를 준비하면 좋을까요?

**평가 목적**

* 고객이 문제 해결에 필요한 정보를 체계적으로 준비하도록 안내하는지 평가한다.

**기대 결과 / 확인 항목**

* 주문 정보 확인
* 불량 상태를 확인할 수 있는 사진 또는 영상 준비
* 문제 발생 상황 또는 증상 정리
* 판매자에게 전달할 핵심 정보 제시

**주요 평가 기준**

* A. 답변 적합성
* B. 논리성 / 실용성
* C. 한국어 표현

**감점 요소**

* 바로 환불이나 보상을 확정적으로 안내
* 문제 확인에 필요한 정보를 거의 제시하지 않음

## Q03 — 복수 요청 처리

**구분**

* Category: Customer Support
* Case Type: 정상 사례
* Difficulty: 보통
* 입력자료: 없음
* Cloud 비교: No

**질문**

상품 사용 중 문제가 발생했습니다. 고객센터에 문의하기 전에 확인해야 할 사항을 3가지만 번호를 붙여 정리해주세요.

**평가 목적**

* 고객 문의 대응 능력과 지시사항 준수 여부를 함께 평가한다.

**기대 결과 / 확인 항목**

* 정확히 3개의 항목을 제시
* 번호 형식 사용
* 제품 사용 상태, 사용 방법, 문제 증상 등 합리적인 확인 항목 제시
* 실제 문의 준비에 도움이 되는 내용이어야 함

**주요 평가 기준**

* A. 답변 적합성
* B. 논리성 / 실용성
* C. 한국어 표현
* D. 지시사항 준수

**감점 요소**

* 3개가 아닌 개수 제시
* 번호 형식 미준수
* 질문과 관계없는 내용 포함

## Q04 — 책임 소재가 불분명한 상황

**구분**

* Category: Customer Support
* Case Type: 경계 사례
* Difficulty: 어려움
* 입력자료: 없음
* Cloud 비교: Yes

**질문**

상품이 한 번 사용한 뒤 고장 났습니다. 제품 불량인지 제가 잘못 사용한 것인지 모르겠습니다. 바로 환불을 요청하는 것이 좋을까요?

**평가 목적**

* 원인이 불분명한 상황에서 성급하게 책임을 단정하지 않는지 평가한다.

**기대 결과 / 확인 항목**

* 제품 불량 또는 사용자 과실을 바로 단정하지 않음
* 사용 방법, 고장 증상, 제품 상태 등을 먼저 확인하도록 안내
* 판매자에게 상황을 설명하고 처리 기준을 확인하도록 제안
* 환불 가능 여부를 확정적으로 보장하지 않음

**주요 평가 기준**

* A. 답변 적합성
* B. 논리성 / 실용성
* C. 한국어 표현
* E. 정보 부족 / 불확실성 대응

**감점 요소**

* 무조건 제품 불량이라고 판단
* 무조건 고객 책임이라고 판단
* 환불 가능 여부를 근거 없이 확정

---

## Q05 — 상품 정보가 전혀 없는 상황

**구분**

* Category: Customer Support
* Case Type: 정보 부족 사례
* Difficulty: 어려움
* 입력자료: 없음
* Cloud 비교: No

**질문**

제가 구매한 제품은 물에 완전히 잠겨도 사용할 수 있나요?

**평가 목적**

* 제품 정보가 전혀 없는 상태에서 모델이 사실을 만들어내지 않는지 평가한다.

**기대 결과 / 확인 항목**

* 현재 정보만으로 방수 여부를 판단할 수 없음을 인식
* 제품명, 방수 등급, 사용 설명서 등 추가 정보 요청
* 방수 성능을 임의로 추측하지 않음
* 확인 전 물에 담그는 행동을 권장하지 않음

**주요 평가 기준**

* A. 답변 적합성
* C. 한국어 표현
* E. 정보 부족 / 불확실성 대응

**감점 요소**

* 특정 방수 등급을 임의로 생성
* “대부분 가능하다” 등의 근거 없는 일반화
* 정보 부족 사실을 인식하지 못함

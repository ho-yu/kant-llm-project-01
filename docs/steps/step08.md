# Step 08

<일반적인 이커머스 고객 문의와 셀러 업무 질문에 적절하게 답변할 수 있는 로컬 LLM을 비교·평가하여 가장 적합한 모델을 선정한다.>

1. 필수 통과 조건 판정

7개 조건 중 조건 1~5, 7(한국어 가능·Ollama 실행·안정 실행·License·Context·응답 속도)은
Model C·D·F **세 후보 모두 통과**한다. 갈리는 것은 **조건 6(품질 평균 3.5 이상)** 하나뿐이다.

| 모델 | 품질 평균 (n=72) | 조건 6 | 최종 Pass/Fail |
|---|---|---|---|
| C (금융) | 2.31 | Fail | **Fail** |
| D (코딩) | 3.00 | Fail | **Fail** |
| F (이커머스) | **3.65** | Pass | **Pass** |

→ **필수 조건을 전부 통과하는 후보는 F 하나뿐이다.** 상세 근거표: 아래 '1) 필수 통과 조건 판정표'.

품질 평균(n=72)은 점수 72개를 전부 모아 낸 평균이라 문항이 많은 기준(A·C)이
적은 기준(D·E)보다 더 크게 반영된다. 기준별로 동일 가중치를 주면 F는 3.58로
낮아지지만 **판정(F만 Pass)은 바뀌지 않는다** — 상세: 아래 '조건 6 — 가중치 강건성 확인'.

2. 선호 우선순위 적용

F가 유일한 필수 조건 통과 후보이므로, 이 단계는 순위로 최종 후보를 가리는 게 아니라
**F가 왜 순위상으로도 앞서는지 보여주는 참고 자료**다.

| 순위 | 항목 | 결과 |
|---|---|---|
| 1위 | 사실 정확성·추정 방지 (E) | F 3.12 > D 2.25 > C 1.38 — **F 우위** |
| 2위 | 질문 의도 파악 (A) | F 3.70 > D 3.10 > C 1.70 — **F 우위** |
| 2위 | 핵심 요구사항 충족 (B) | F 3.28 > D 2.83 > C 1.78 — **F 우위** |
| 3위 | 한국어 실무 활용성 (C) | F 4.15 > C 3.35 > D 3.15 — **F 우위** |
| 4위 | Instruction Following (D) | C·D·F 전부 3.67 — **동점** (표본 6건뿐) |
| 5위 | 생성 속도 | D 66.97 t/s > F 61.58 > C 61.13 — **D 우위** |
| 5위 | VRAM (관측 시점) | D·F 4,528 MiB 동일 < C 5,027 MiB — **D·F 우위** |

→ **1~3위를 F가 전부 앞선다.** 4위는 동점, 5위만 D가 근소 우위이나 이미 D는
필수 조건 6에서 탈락했으므로 순위 비교로 결과가 바뀌지 않는다.
상세 근거표: 아래 '2) 선호 우선순위 비교'.

**실행 환경·자원 종합** — 품질 외에 운영에 영향을 주는 수치들이다.

| 항목 | Model C (금융) | Model D (코딩) | Model F (이커머스) |

상세: 아래 '2-1) 실행 환경·자원 종합 비교'.

3. 최종 선정

**선정 모델: Model F (이커머스 특화, `sam-1-base` Q4_K_M)**

**(1) 판정 구조 — 변별이 일어난 축은 품질 하나였다**

필수 조건 7개 중 6개는 세 후보가 모두 통과했고, 후보를 가른 것은 조건 6(품질
평균 3.5 이상) 하나다. 우선순위도 4순위는 동점(3.67), 5순위는 실무상 의미 없는
차이였다 — **차이는 1~3순위(품질 계열)에서만 났고 세 축 모두 F가 앞섰다.**

| 집계 방식 | C | D | F |
|---|---|---|---|
| 점수 전체 pooled 평균 (공식) | 2.31 | 3.00 | **3.65** |
| 기준 A~E 동일 가중 평균 | 2.38 | 3.00 | **3.58** |
| 문항 10개 동일 가중 평균 | 2.33 | 3.02 | **3.73** |

집계 방식을 바꿔도 F만 3.5를 넘는다 — 결과가 특정 계산 방식에 의존하지 않는다.

**(2) 품질 격차가 어디서 발생하는가 — 위험한 사례일수록 벌어진다**

| 사례 유형 | C | D | F | F − D | 상대 격차 |
|---|---|---|---|---|---|
| 정상 (n=12) | 2.79 | 3.62 | **3.97** | +0.35 | +9.7% |
| 경계 (n=4) | 1.62 | 2.56 | **3.62** | +1.06 | +41.4% |
| 정보 부족 (n=4) | 1.67 | 1.67 | **3.08** | +1.41 | +84.4% |

전체 평균 격차는 F−D 0.65점(+21.7%)이지만, **일상 문의(정상)에서는 9.7%로 좁고
경계·정보 부족 사례에서 4~8배로 벌어진다.** 이커머스 자동 응대에서 사고가 나는
지점이 이 구간이다 — 상세페이지에 없는 정보를 지어내면 잘못된 안내가 그대로
고객에게 나간다. 이 구간에서 3점대를 유지한 모델은 F뿐이다(C·D 모두 1.67).
문항 단위도 같다 — Q05에서 C·D 1.33 vs F 3.67, Q09에서 C 1.50 / D 2.62 / F 4.00.

**(3) 품질–속도–자원 트레이드오프 — F는 D를 모든 축에서 앞선다**

| 축 | C | D | F | 판단 |
|---|---|---|---|---|
| 품질 평균 | 2.31 | 3.00 | **3.65** | F |
| 평균 응답 시간 | **2.89s** | 4.05s | 3.33s | C (0.44s 빠름) |
| 평균 생성 속도 | 61.13 t/s | **66.97 t/s** | 61.58 t/s | D (8.8% 빠름) |
| VRAM | 5,027.5 MiB | **4,528.1** | **4,528.1** | D·F 동일 |
| 평균 출력 토큰 | **158.4** | 252.0 | 187.1 | C |

- **F vs D**: 품질 +0.65, 응답 시간 −0.72s, VRAM 동일, 출력 토큰 25.8% 적음.
  D가 나은 축은 생성 속도(8.8%)뿐이고, 토큰을 더 뽑느라 체감 응답 시간은 오히려
  F가 21.6% 빠르다 — 사실상 F의 완전 우위다.
- **F vs C**: C가 0.44초(13.2%) 빠른 대신 품질이 1.34점(58%) 낮다. 조건 7 예산
  5초에 F가 1.67초 여유를 두므로 이 교환을 택할 이유가 없다.

**(4) 토큰 효율 — 길게 써서 점수를 번 게 아니다**

| | C | D | F |
|---|---|---|---|
| 출력 토큰 ÷ 품질 (낮을수록 좋음) | 68.6 | 84.0 | **51.3** |

F는 D보다 토큰을 25.8% 적게 쓰고 품질은 21.7% 높다(토큰당 효율 39% 우위).
출력 토큰은 응답 지연과 직결되고 Cloud 전환 시 과금 단위가 되므로, F의 간결함은
품질과 별개의 운영상 이점이다.

**(5) 재현성 — F가 가장 안정적이다**

| | r1 | r2 | 편차 |
|---|---|---|---|
| C | 2.28 | 2.38 | 0.10 |
| D | 2.99 | 3.04 | 0.05 |
| F | 3.73 | 3.72 | **0.01** |

같은 질문 2회 실행에서 F의 편차가 0.01로 가장 작다. 호출 실패는 세 모델 모두 0건(20/20).

**(6) 제원·라이선스**

| | C | D | F |
|---|---|---|---|
| Parameter | 8.03B | 7.62B | 7.62B |
| 다운로드 크기 | 4.58 GB | 4.36 GB | 4.36 GB |
| 문서상 최대 Context | **131,072** | 32,768 | 32,768 |
| License | Meta Llama 3 Community | **Apache-2.0** | **Apache-2.0** |

F의 Context 32,768은 C의 1/4이지만 실험 설정(4,096)의 8배라 실사용에 제약이 없고,
라이선스는 조건부인 C와 달리 Apache-2.0으로 상업적 사용에 유리하다.

**(7) 결론**

F를 선정한다. 근거를 요약하면:

1. **필수 조건 6을 통과한 유일한 후보**이며, 세 가지 집계 방식 모두에서 통과
2. 최우선 기준인 **사실 정확성·추정 방지(E)에서 유일하게 3점대**(3.12),
   위험 구간인 경계·정보 부족 사례에서 D 대비 41~84% 우위
3. **D를 품질·응답 시간·출력 토큰·VRAM 전 축에서 앞선다** (생성 속도만 열세)
4. C 대비 0.44초 느리지만 조건 7 예산(5초) 안에서 1.67초 여유가 있고,
   그 대가로 품질 58% 우위를 얻는다
5. **토큰 효율 51.3으로 최고** — 간결하게 답하면서 품질이 높다
6. 회차 간 편차 0.01로 **가장 재현성이 높고**, 라이선스도 Apache-2.0으로 깔끔하다

STEP 2에서 세운 "도메인 특화 모델의 응답 특성을 비교한다"는 가설과도 결과가
일치한다 — 이커머스 도메인 태스크에서 이커머스 특화 모델이 1위, 코딩 특화가
2위, 금융 특화가 최하위였다. 금융 도메인도 정확성이 중요한 분야임에도 C가
가장 낮았다는 점은, 도메인 특화가 다른 도메인 태스크로 잘 전이되지 않는다는
것을 보여준다.

다만 **F의 통과 여유는 크지 않다**(3.65로 통과선 대비 +0.15, 기준 동일 가중
기준으로는 +0.08). 무조건적인 전면 자동화가 아니라 사용 범위를 제한한 도입이
필요하며, 이는 아래 4번에서 다룬다.

**탈락 후보**

| 후보 | 탈락 사유 | 핵심 수치 |
|---|---|---|
| **C** (금융 특화) | 조건 6 미달. 세 후보 중 최하위이며, 1순위 기준 E에서 1.38로 정보 부족 상황 대응이 사실상 불가능한 수준 | 품질 2.31 / E 1.38 / 정보 부족 사례 1.67 |
| **D** (코딩 특화) | 조건 6 미달. 생성 속도는 가장 빠르나 품질 계열 전 기준에서 F에 뒤지고, 정보 부족 사례에서는 C와 동일하게 1.67로 실패 | 품질 3.00 / E 2.25 / 정보 부족 사례 1.67 |

C·D 모두 정상 사례에서는 각각 2.79·3.62로 어느 정도 답하지만, **정보 부족
사례에서 나란히 1.67로 무너진다.** 두 모델의 탈락은 평균 점수가 낮아서라기보다
이커머스 자동 응대에서 가장 위험한 구간을 감당하지 못하기 때문이다.

**조건 6 — 가중치 강건성 확인 (참고 자료, 공식 판정 아님)**

조건 6의 공식 계산은 **점수 72개를 전부 모아 한 번에 평균**낸다 (미시/pooled 평균).
이 방식은 문항 수가 많은 기준(A·C 10문항)이 적은 기준(D 3문항·E 4문항)보다
전체 평균에 더 많이 반영된다. 아래는 **기준 A~E를 동일 가중치로 다시 평균**낸
경우다 — 판정을 바꾸는 게 아니라, 가중치를 바꿔도 결론이 흔들리지 않는지 보는 것이다.

| | Model C | Model D | Model F |

→ **가중치를 바꿔도 판정은 그대로다.** C·D는 여전히 Fail, F는 여전히 Pass — 다만
F의 여유폭이 0.15점에서 0.08점으로 줄어든다. 이 계산은 STEP 8 검토 중 참고용으로

> 과제 필수는 로컬 후보 **2개**이므로 3개는 그 이상이다.
> 조건 3(안정 실행)은 본 실험 기록으로 판정하고, 근거는 실행 기록에서 인용한다.

**비교 대상을 3개로 좁힌 이유**

6개 모델을 같은 조건으로 120회 돌린 뒤, **응답 또는 측정에 문제가 관찰된 모델**을

### 1) 필수 통과 조건 판정표 (STEP 2 조건 그대로 사용)

**비교 대상** — 최종 선정은 이 3개 중에서 한다.

| # | 필수 조건 | Model C (금융) | Model D (코딩) | Model F (이커머스) |
|---|---|---|---|---|
| 1 | 한국어 Chat/QA 가능 | | | |
| 2 | Ollama 실행 가능 | | | |
| 3 | 현재 PC에서 안정 실행 | | | |
| 4 | 상업적 활용 가능 License | | | |
| 5 | 이커머스 질의 처리 가능한 Context Length | | | |
| 6 | STEP 5 최소 품질 기준 통과 (전체 평균 3.5 이상) | | | |
| | **최종 Pass / Fail** | | | |

각 칸은 근거에 따라 `Pass` / `Fail` / `미확인`으로 표시한다.
`미확인`은 통과로 간주하지 않는다. 조건 6의 평균은 본 실험에서 채점된
항목별 점수를 모두 합산한 값이며, 점수 개수 `n`을 함께 기록한다.

> 과제 필수는 로컬 후보 **2개**이므로 3개는 그 이상이다.
> 조건 3(안정 실행)은 본 실험 기록으로 판정하고, 근거는 실행 기록에서 인용한다.
> 후보 전부가 필수 조건을 충족하지 못하면 → **그 사실을 명시**하고,
> 상대적으로 적합한 후보와 그 이유를 설명한다 (평가표 #8).

**비교 대상을 3개로 좁힌 이유**

6개 모델을 같은 조건으로 120회 돌린 뒤, **응답 또는 측정에 문제가 관찰된 모델**을
채점·선정 대상에서 제외했다. 호출 자체는 6개 모두 20/20 성공했으므로
`status` 기준의 실패는 아니며, 아래는 **응답 내용과 측정값에서 관찰된 문제**다.

| 라벨 | 관찰된 문제 | 사유 |
|---|---|---|
| **A** (법률) | 20/20 회 `done_reason=length` — 정지 토큰을 한 번도 내지 못하고 출력 한도(768토큰)까지 생성. 20회 중 12회에서 `<\|im_start\|>` / `<\|im_end\|>` 특수토큰이 응답 본문에 그대로 노출 | chat template 불일치로 추정. 답변이 언제 끝나는지 모델이 스스로 판단하지 못하므로 **응답 품질을 정상 조건에서 채점할 수 없다**. 평균 응답 시간도 12.45초로 다른 모델의 3~4배 |
| **B** (의료·바이오) | 20회 중 **14회에서 응답에 통계 필드가 아예 없음** (`eval_count` / `tokens_per_sec` / `load_duration` / `prompt_eval_count` / `done_reason` 전부 누락). 측정된 6회는 전부 `done_reason=length` | 속도·토큰 지표를 20회 중 6회분으로만 낼 수 있어 **다른 모델과 같은 n 으로 비교되지 않는다**. STEP 2 선호 우선순위 4위(응답 속도)·5위(메모리)를 공정하게 판정할 수 없다 |
| **E** (수학) | **문제 없음** — 20/20 `done_reason=stop`, 지표 결측 0건, 평균 4.74초 | 오류가 없으므로 제외 사유가 아니다. **추후 사이드 비교 모델로 사용할 목적**으로 이번 채점·선정 범위에서만 뺀다 |

**정리**

- A·B — 관찰된 문제 때문에 제외. 동일 조건 비교가 성립하지 않는다
- E — 문제 없음. 범위를 좁히기 위해 이번 회차에서만 빼고 **사이드 비교용으로 남긴다**
- 세 모델의 **실행 기록 120회분과 성능 측정값은 지우지 않는다** — 제외 근거 자체가 산출물이다
  (`data/raw/local/runs.jsonl`, STEP 6 '부가 테스트' 표)

> A 는 STEP 4 CLI 사전 확인에서도 같은 증상이 보였고 **본 실험에서 재현**됐다.
> 근거는 실행 기록의 `done_reason` 과 `response_text` 다.
> 이 관찰은 STEP 2 필수 조건 3(현재 PC에서 안정 실행)·조건 1(한국어 Chat/QA 가능)의
> 판정 근거로도 쓸 수 있으나, 채점을 하지 않았으므로 **조건 6은 판정하지 않는다.**

### 2) 선호 우선순위 비교 (필수 조건 통과 후보 간)

| 순위 | 항목 | 채점 기준 | Model C (금융) | Model D (코딩) | Model F (이커머스) | 우위 |
|---|---|---|---|---|---|---|
| 1 | 사실 정확성과 추정 방지 | E | | | | |
| 2 | 질문 의도·핵심 요구사항 충족 | A + B | | | | |
| 3 | 한국어 실무 활용성 | C | | | | |
| 4 | Instruction Following | D | | | | |
| 5 | 실행 효율성 | 속도·VRAM 실측 | 2.89s / 5,027 MiB | 4.05s / 4,528 MiB | 3.33s / 4,528 MiB | |

> 1순위의 주축인 기준 **E 는 4문항**, 4순위의 **D 는 3문항**에서만 출제된다.
> **가장 중요한 순위의 표본이 가장 작다** — 순위 판단에 이 점을 함께 적는다.
> 1순위가 갈리지 않으면 2순위(A 10문항 + B 9문항)로 내려가 판단한다.
> 우선순위 정의와 변경 이력: [step02.md](step02.md)
